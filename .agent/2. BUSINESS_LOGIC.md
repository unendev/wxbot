# BUSINESS_LOGIC.md

## 核心业务流 (Core Business Flow)

### 1. 后台静默监听 (Silent Listening)
* 脚本周期性（默认 1 秒）调用 `wxauto` 获取当前聊天窗口的新消息。
* 过滤消息发送者，防范死循环：如果是机器人小号自身发出的消息，直接忽略。
* 识别消息中是否包含 `@机器人` 的文本。

### 2. 文本解析与敏感词过滤 (Text Parsing & Safety Filter)
* 去除 `@机器人` 标识，提取用户真实问题。
* 通过本地自定义的关键词敏感词列表（如政治、广告等违规词）进行前置拦截。如果命中，直接返回一条幽默的拒绝回复，不再请求 LLM，以节省 Token 并保证安全。

### 3. 大模型调用 (LLM Inference)
* 异步/同步将提取的问题打包发送给 LLM。
* 设定 System Prompt，让模型理解自己是群聊里的幽默助手，可以根据语境要求在结尾以特定格式触发表情包输出，例如 `[发表情:狗头]`。

### 4. 响应分流与无感回复 (Response Dispatching & Silent Sending)
* 接收到 LLM 响应后，使用正则表达式匹配表情包指令：
  * **文字部分**: 剥离表情包指令，得到纯文本。
  * **表情包部分**: 解析出需要发送的本地图片键名（如 `狗头`）。
* **发送流程**:
  * 如果有文本，通过 UI 自动化直接将 Value 赋值给输入框，并发送回车信号。
  * 如果有表情包，将对应的图片读入剪贴板，使用 `0.05` 秒的聚焦粘贴逻辑，发送后立即恢复用户原本的剪贴板内容。
